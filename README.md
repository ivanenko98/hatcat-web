# Inverter Monitor (веб-клиент для аккаунта HATCAT)

Личный веб-дашборд для мониторинга своего инвертора через тот же облачный API,
что использует Android-приложение HATCAT (`https://hatcat.eu/auth/`).
Только чтение: логин, список устройств, текущие данные. Настройки не меняются.

## Запуск

Нужен Node.js 18+, зависимостей нет.

```bash
node server.js                 # http://127.0.0.1:8080, реальный API
MOCK=1 node server.js          # демо-данные, аккаунт не нужен
CAPTURE=1 node server.js       # плюс сохранять ответы API в ./captures
PORT=3000 HOST=0.0.0.0 node server.js   # доступ из локальной сети
```

Зачем сервер: браузер не даст странице напрямую ходить на hatcat.eu (CORS),
поэтому `server.js` отдаёт страницу и проксирует 4 эндпоинта:
`m_login`, `m_get_my_device`, `m_get_device_data`, `m_get_device_settings`.
Остальные (регистрация, добавление устройства, запись настроек) закрыты.

## Что известно из APK, а что угадано

Из бинарника (Flutter, `libapp.so`) точно известно:
- эндпоинты и что тело запроса `application/x-www-form-urlencoded`, есть `Bearer`-токен;
- имена полей: `user_email`, `user_password`, `user_token`, `user_id`,
  `id_device`, `mac_address`, `dev_type`, `raw_val`, `day_accumulated`,
  `tempBMS`, `tempCells`, `tempInv`, `pvInputPower`, `outFreq` и др.

Угадано (полный декомпилятор в этой среде запустить не удалось):
- точная структура ответов. Поэтому клиент разбирает ответ «гибко»:
  ищет токен по ключу `*token*`, массив устройств в любом месте ответа,
  поля по таблице синонимов, а строку вида `(230.0 50.0 ...)` парсит
  как ответ `QPIGS` инверторов Voltronic/Axpert (у HATCAT тот же набор
  настроек prog01…prog45, так что это вероятный формат `raw_val`).
- запрос шлёт и Bearer-заголовок, и `user_id`/`user_token` в теле.

## Откуда берутся данные (проверено на реальном ответе)

`m_get_my_device` возвращает и список устройств (`devices`), и последние
показания в `mas_powerstation` (регистры `K1…K36`, время `Time` в unix-секундах).
Клиент опрашивает его каждые 30 секунд. `m_get_device_data` с теми же
параметрами отвечает `401 The session is expired`, поэтому используется только как запасной путь.

Расшифровка регистров (`KMAP` в `public/index.html`). Уверенно: K6 батарея V×0.1,
K7 заряд %, K10/K11 выход V×0.1 / Hz×0.1, K12 VA, K13 W, K14 загрузка %.
Остальное подобрано по значениям и помечено «?» в блоке «Сырой ответ».
Проверить проще всего так: открыть приложение и сравнить цифры.

## Если что-то показывается неправильно

1. Запустить `CAPTURE=1 node server.js`, войти, подождать одно обновление.
2. В папке `captures/` будут ответы сервера (пароль в логах замаскирован,
   токен остаётся, так что перед пересылкой лучше его затереть).
3. Блок «Сырой ответ API и все поля» внизу страницы показывает то же самое.

По этим ответам маппинг полей (`ALIASES` и `parseQpigs` в `public/index.html`)
подгоняется за несколько минут.

## Безопасность

- Сервер по умолчанию слушает только `127.0.0.1`. Если открываете наружу,
  ставьте его за HTTPS (nginx/Caddy) и, желательно, basic auth.
- Токен хранится в `localStorage` браузера, пароль не сохраняется.
- Это неофициальный клиент: если HATCAT поменяет API, его придётся поправить.
