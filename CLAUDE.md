# HATCAT web monitor

Особистий веб-дашборд інвертора через неофіційний доступ до API застосунку HATCAT (`https://hatcat.eu/auth/`). Тільки читання.

Документи (читати перед роботою над функціоналом):
- `docs/API.md`: хмарне API, K-регістри телеметрії, P-регістри налаштувань, позначки впевненості ✅/🟡/❓;
- `docs/PRODUCT.md`: опис продукту і скоуп;
- `docs/SPEC.md`: технічне завдання, етапи, критерії приймання;
- `docs/TASKS.md`: розбивка на задачі та їхній статус. Оновлювати після кожної виконаної задачі.

Ключові факти про API (режим K1: 3 від батареї, 4 від мережі, 6 аварія; K2/K3 мережа, K8 струм заряду, K15/K16 маски аварій і попереджень): сервер вимагає `User-Agent: Dart/3.7 (dart:io)`; `m_get_device_settings` приймає `device_id` (не `id_device`); `m_get_device_data` не працює, а вся телеметрія є в `m_get_my_device`.

## Структура

- `server.js`: Node 18+, без залежностей. Віддає `public/` і проксіює `POST /api/<endpoint>` на hatcat.eu. Пропускає лише ендпоінти з `ALLOWED`; там же лежать мок-дані для `MOCK=1`.
- `history.js`: запис історії. Сесія береться з логіну й опитувань браузера через проксі (`data/session.json`, права 0600, пароль не зберігається). Раз на 60 с сервер сам викликає `m_get_my_device` і дописує `data/history/<device>/<дата>.jsonl`. Запис зупиняється, коли токен протухає (~7 днів), і відновлюється після наступного входу в браузері. `GET /history/...` вимагає Bearer-токен.
- `limits.js`: ліміти (`data/limits.json`, ендпоінт `/limits`): ввідний автомат 25 А і номінал інвертора станції 4200 ВА (паспорт: `docs/DEVICE_SPEC.md`), пороги 80 % і 95 % від кожного. Повідомляє про вихід за межі і радить струм заряду (програма 11). і оцінка струму мережі `gridAmps` = (повна потужність виходу K12 + потужність заряду K6×K8 ÷ 0,93) ÷ напруга мережі K2, лише в режимах «від мережі» й «байпас». Дзеркало цієї формули є в `public/js/regs.js` (`gridAmps`); при зміні правити обидва.
- `outages.js`: графік планових відключень (ГПВ) Полтаваобленерго. Кожні 30 хв робить 3 запити до `www.poe.pl.ua` (`POST /customs/newgpv-info.php` на сьогодні й завтра, `/customs/unloading-info.php` для аварійних відключень ГАВ) із чесним User-Agent, розбирає HTML (48 півгодинних клітинок на 12 черг, `gpv-s1` світло, `s2` відключення, `s3` перемикання), кешує в `data/outages-cache.json`, черга в `data/outages.json` (за замовчуванням 5.1). Ендпоінт `/outages` (Bearer). `stateAt/describe` дають «що має бути зараз»; дані старші за 3 год не довіряються. **Не парсити energy-ua.info**: Cloudflare-перевірка й `Disallow: /` у robots.txt.
- `telegram.js`: сповіщення в Telegram. Отримує кожен новий зріз телеметрії від `history.js` (`setNotifier`) і раз на хвилину `tick`; події: нові й усунуті аварії та попередження (K15/K16), зникнення й повернення мережі (K2, підтвердження за 2 зрізи), струм мережі біля ввідного автомата, позапланове відключення (світла немає ≥ 5 хв, хоча за графіком черги мало бути), низький заряд 20/10/5 %, станція не на зв'язку, спливає сесія. Конфіг у `data/telegram.json` (права 0600, токен бота лише там), стан у `data/telegram-state.json`. Чат прив'язується одноразовим кодом, який користувач шле боту. Ендпоінти `/telegram/*` вимагають Bearer-токен, як і `/history`. Для тестів `TELEGRAM_API=http://127.0.0.1:<порт>` підміняє api.telegram.org.
- `public/`: фронтенд на нативних ES-модулях, без збірки.
  - `index.html` (оболонка), `css/app.css` (токени HATCAT, світла й темна теми);
  - `js/main.js`: хеш-роутер (`#/devices`, `#/device/<id>`, `#/profile`, `#/login`) і опитування `m_get_my_device` раз на 30 с;
  - `js/api.js`: запити до проксі, сесія, термін дії токена;
  - `js/regs.js`: `KMAP` (регістри `K1…K36`), режими, `telemetry(row)`;
  - `js/alerts.js` + `alerts-text.js`: аварії й попередження з бітових масок K15/K16, тексти з застосунку, кожен запис має `kind`; `notify-prefs.js` вмикає/вимикає види сповіщень для сайту (localStorage), для Telegram це `telegram.json`; `programs.js`: програми станції;
  - `js/i18n.js` (uk, en), `fmt.js`, `dom.js` (`h()` будує DOM без innerHTML), `theme.js`, `store.js`;
  - `js/views/*.js`: екрани (`station`, `history`, `settings`, `notifications`, `devices`, `profile`, `login`). Профіль `#/profile/<розділ>` складається з `profile.js` (рейка й розділ «Обліковий запис») та розділів `notifications-card.js`, `telegram-card.js`, `outages-card.js`, `limits-card.js`; спільні контроли (перемикач, тост, segmented) у `js/ui.js`;
  - `js/charts.js`: власні SVG-графіки (лінійний і стовпчастий) з підказками й таблицею;
  - `assets/` і `fonts/`: іконки, зображення та шрифт Source Sans 3 з APK.
- `reverse/`: декомпільований код застосунку (blutter) і мої інструменти, лише локально (`.gitignore`). Опис у `reverse/README.md`; таблиця «програма → регістр» лежить у `reverse/blutter-out/pp.txt`.
- `HATCAT_v2026.3.24.apk`: оригінальний APK (Flutter, `libapp.so`) для довідки. Не комітити й не редагувати.

## Правила

- Ніколи не проксіювати `m_set_new_settings` і `m_add_new_dev`. Налаштування станції лише читаємо.
- Без npm-залежностей і збірки. Нові екрани додавати модулями у `js/views/`, тексти лише через `t()` в обох мовах.
- Дані з API вставляти тільки текстом (`h()`), без `innerHTML`.
- Невпевнені регістри не позначати `sure:true`: у UI вони показуються з «?».
- `captures/`, `data/session.json` і `data/telegram.json` містять токени. Не виводити їх вміст і нікуди не пересилати. Токен бота не віддавати у відповідях API й не писати в логи.

## Запуск і деплой

Працює постійно як systemd user-сервіс (`~/.config/systemd/user/hatcat-web.service`) на `127.0.0.1:8080`:

```bash
systemctl --user restart hatcat-web    # після змін у server.js (статика підхоплюється без рестарту)
journalctl --user -u hatcat-web -f     # логи
```

Для локальної розробки без акаунта, на іншому порту: `MOCK=1 PORT=8081 node server.js` (вхід з будь-яким email і паролем).

Доступ ззовні йде через Tailscale Serve (тільки tailnet, не Funnel): `https://desktop.tailaa9873.ts.net` → `127.0.0.1:8080`. Сервер має слухати лише `127.0.0.1`. Публічний доступ (`tailscale funnel`) вмикати тільки після додавання авторизації в `server.js`.

Node з nvm (`/home/oleh/.nvm/versions/node/v20.20.0/bin/node`). Після оновлення Node поправити `ExecStart` у юніті.
