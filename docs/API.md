# HATCAT cloud API (реверс-інжиніринг)

Стан на 2026-10-28. Джерела:
- рядки з `libapp.so` у `HATCAT_v2026.3.24.apk` (Flutter AOT, Dart 3.7). Повного декомпілятора не запускали, тому структура коду невідома, видно лише рядки;
- живі запити до `hatcat.eu` з акаунта власника (device 64, `dev_type=1`, power station).

Позначки: ✅ перевірено живим запитом · 🟡 видно в APK, параметри частково вгадані · ❓ невідомо.

## Загальне

- База: `https://hatcat.eu/auth/<endpoint>`, метод `POST`, тіло `application/x-www-form-urlencoded`.
- **Обов'язковий `User-Agent: Dart/3.7 (dart:io)`.** Без нього сервер відповідає на частину ендпоінтів `{"status":403,"message":"Access denied!"}` ✅.
- Авторизація: `user_id` + `user_token` у тілі. Додатково `Authorization: Bearer <user_token>`: сервер його приймає, але для `m_get_my_device` і `m_get_device_settings` він не обов'язковий ✅.
- HTTP-статус завжди 200. Справжній статус лежить у полі `status` JSON-відповіді (`200`, `401`, `403` …), поряд іде текст у `message` ✅.
- Усі числа приходять **рядками** (`"K6":"509"`) ✅.

### Токен

`user_token` у base64 має вигляд `<user_id>:<expires_unix>:<hex sha256-hmac>` ✅. Живе ~7 днів: виданий 28.10 14:56, діє до 04.11 14:56. Перевірити термін можна без запиту на сервер, якщо декодувати середню частину. Ендпоінта refresh не знайдено, тож після закінчення терміну треба знову логінитися.

## Ендпоінти

### `m_login` 🟡
Запит: `user_email`, `user_password`. Відповідь (зі старого перехоплення та моку): `status`, `user_id`, `user_token`. Помилки текстом у `message`.

### `m_get_my_device` ✅
Запит: `user_id`, `user_token`, `user_email`. Інші параметри ігноруються, зокрема `send_day_values`, `device_id`, `date`: відповідь не змінюється.
```json
{
  "status": 200, "message": "Data received successfully",
  "devices": [{"device_id":"64","created_at":"2026-10-28 14:09:27","name":null,
               "mac_address":"74E9D8092A6E","dev_type":"1","deviceTimeZone":"Europe/Kyiv"}],
  "mas_powerstation": [{"id_device":"64","Time":"1793192610","K1":"3", "...":"...", "K36":"238"}],
  "mas_battery": [], "mas_battery_new": []
}
```
- `devices[]` містить усі пристрої акаунта, і власні, і поширені (shared).
- `mas_powerstation[]` містить останній зріз телеметрії по кожній станції (`dev_type=1`). `Time` — unix-секунди, коли зріз потрапив на сервер.
- `mas_battery[]` / `mas_battery_new[]` — телеметрія батарейних модулів (`dev_type`, ймовірно, `2`). Формат ❓: модуля в нас немає. За рядками UI там є напруги комірок, кількість циклів, ємність, температура комірок і BMS (min/max).
- Як часто модуль шле дані ❓. Сайт опитуємо раз на 30 с.

### `m_get_device_settings` ✅
Запит: `user_id`, `user_token`, `user_email`, **`device_id`**. Якщо передати `id_device` або тільки `mac_address`, сервер відповідає `403 "You do not have permission to modify this device"`.
```json
{"status":200,"message":"Data received successfully",
 "mas_settings":{"P1":"0","P2":"440", "...":"...", "P48":"106","P65535":"1793189388"}}
```
`P65535` — unix-час, коли інвертор востаннє надіслав налаштування. Розшифровку див. нижче.

### `m_get_device_data` ❓
Відповідає `401 "The session is expired"` на всі перевірені комбінації: `id_device`/`device_id`, `mac_address`, `dev_type`, `date`, `time`, `send_day_values`, з Bearer і без. Можливо, потрібен інший токен (у бінарнику є ключі `secret_key` і `last_sync_`) або ендпоінт застарів. **Не використовувати.** Усе потрібне вже є в `m_get_my_device`.

## Струм з мережі (оцінка)

Хмара не віддає струм мережі. Оцінка: `I ≈ (K12 + K6·0.1·K8 / 0.93) / (K2·0.1)`, тобто повна потужність виходу (ВА) плюс потужність, що йде в батарею (з поправкою на ККД зарядки), поділена на напругу мережі. Рахується лише в режимах K1 = 4 (від мережі) і 5 (байпас). При 220 В автомат 25 А це близько 5,5 кВт. Оцінка ще не звірена з реальним вимірюванням, тому в інтерфейсі стоїть «?».

## Що показує головний екран застосунку (для паритету)

## Що ще є в мобільному застосунку, але не в хмарному API

- **Провізія Wi-Fi-модуля** («Hatcat Remote Monitoring Starter Kit», модуль Hi-Flying). Застосунок підключається до точки доступу модуля, шле йому SSID і пароль домашньої мережі та конфіг `{"JCMD":1,"PL":{"SOCK":{"Protocol":"TCP-CLIENT","Server":"hatcat.eu","ServerPort":57900,"RegistMode":"Link","RegistCode":"%HMAC","Name":"netp"}},"CID":10005}`, перезавантажує модуль, після чого викликає `m_add_new_dev`. Із браузера це неможливо, бо немає доступу до Wi-Fi і локальних сокетів.
- **Поширення пристрою**: генерація QR / коду на телефоні власника. Формат коду ❓.
- Локальні налаштування: мова (en/uk/ru), тема (system/light/dark), біометрія, аватар.
- Сповіщення в застосунку («No active notifications across all devices») формуються з аварій і попереджень у телеметрії.
